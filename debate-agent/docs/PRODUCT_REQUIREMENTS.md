# 产品需求：框架稿 Agent

**状态：** 当前产品方向，待双方确认评测细则。本文只定义用户价值与范围；实现边界见 [架构与契约](ARCHITECTURE.md)，阶段见 [开发计划](DEVELOPMENT_PLAN.md)，首版验收见 [MVP](MVP.md)。

## 1. 产品目标

为辩手提供一个能从辩题、持方、赛制和用户材料出发，先完成题解、经人工确认，再生成**结构化、可编辑、可确认的框架稿**的 Agent。目标是让经审核的提示词/Skill 和写作经验对同一通用模型产生可测量的质量增量，并在约定实验条件下优于通用模型直接生成；**这一效果目前尚未证实**。

框架稿服务备赛和临场使用，至少涵盖立论方向、判准、论点分工、论证机理、现实影响、攻防及待补证据需求。案例、研究和数字不能因模型写得流畅就被当作已核验事实。

## 2. 用户与问题

目标用户为辩手、教练和备赛研究者。通用模型的常见不足是题解不贴持方、判准与论点脱节、论点同质、机理跳步、攻防不对应、编造案例或来源，以及重新生成时覆盖人工修改。用户需要的是**可用来继续备赛的工作稿**，而不是一次性长文本。

我们已有多篇人写的优秀框架稿。它们是方法提炼的候选材料，不自动等于可公开训练数据、可直接复制的新题证据或经过人工确认的规则；先检查授权、记录来源定位、用 AI 初提取后由辩手审核，才能沉淀为可执行规则和 Skill。

## 3. MVP 必备能力

1. **项目输入与恢复**：保存辩题、持方、赛制、发言时长、可选背景与用户要求；用户能再次打开项目。
2. **题解 Agent**：理解输入与可用材料，生成概念定义、讨论范围、正反立场、核心冲突、交锋点、判准和策略候选；完成有限自审，说明不确定处。用户可编辑并确认题解；修改产生新版本且必须重新确认。
3. **框架 Agent**：只在题解当前版本已确认时运行；按确认内容与已批准 Skill 生成主张、互有分工的论点、可展开的机理树、影响、攻防和证据需求；完成有限自审与定向修订。输出先是候选，不覆盖人工领先的工作区编辑。
4. **人工工作区与版本**：用户能查看、编辑、保存并明确确认框架；确认产生不可变版本，可呈现/导出结构化框架稿。正式版本不可被下一次 Agent 运行静默改写。
5. **写作方法的增量验证**：样本标注、规则与 Skill 均有来源和版本；冻结未参与提炼的辩题，与通用模型直接生成进行同条件对照。机器检查结构与可验证错误，辩手匿名盲评内容质量，同时记录成本、耗时与人工修改量。

详细的首版交互、明确不做的内容和验收路径以 [MVP](MVP.md) 为准。

## 4. 后续方向（不承诺 MVP）

- **RSI 经验沉淀**：保留用户提出的名称；其具体含义、输入输出、反馈循环和可用数据范围尚待共同定义。可先收集有授权的人工修改理由和失败案例，但不假定模型会自动学习或修改已批准规则。
- 来源检索与原文定位、证据真实性与论点相关性核验、人工证据审批；来源评级不等于证据批准。
- 自然语言局部修改、框架多方案对比、攻防增强、立论稿生成及与框架版本同步。
- 按实际使用量再考虑更多用户协作、更复杂编排、样本检索或专门训练；不预设向量数据库或微调一定必要。

旧全功能规划中的证据审核、立论稿等是**路线图候选**，不是现阶段“框架稿质量增量”的验收前提。

## 5. 非功能要求与待定项

预期早期并发不高，暂不设定未经测量的 QPS、可用性百分比或复杂分布式部署。仍必须做到：项目隔离与可信身份、持久化任务可恢复、幂等和版本冲突保护、超时/有限重试、日志不泄露凭证与私有稿件、可回溯模型/Prompt/Skill 版本、公开仓库只存获授权内容。这些是正确性与安全底线，不依赖高并发。

在选定部署环境、真实用户规模和模型服务商后，再基于测量确定响应时间、容量、预算与备份恢复目标。当前 GitHub 仓库是 **public**，已有原稿可能出现在历史记录中；新增稿件的公开授权须逐篇确认，`.gitignore` 无法撤销历史公开。
