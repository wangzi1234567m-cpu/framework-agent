## 1. 核心设计原则

### 1.1 两层拆解（结构层 vs 质量层）

一篇好框架稿的质量 = **结构层（机器可自动检查）+ 质量层（必须人工判断）**。

- **结构层（机器查）**：论点句是否一句话可辩驳、是否分层、每层有无中心句、每层有无案例、有无金句、有无短打素材、数据有无出处。
- **质量层（人工判）**：论点精不精简、案例生不生动、价值深不深、跳脱维度成不成立、够不够「耳目一新」。

### 1.2 六条关键判断（从具体稿件提炼）

1. **递进 > 并列**：并列不是不好，但逐层递进更有条理、更能说服人。
2. **论点句要「金句化」**：不只一句话可辩驳，还要有能当标签的小金句（如「反目的、反效率」）。
3. **案例要「比较型 + 铺设框架」**：案例用来铺论点框架、做对照（P图 vs 素颜、包装 vs 真实），不是点缀。
4. **文学语句要「贯穿全文」**：「所爱隔山海」「乡愁是一枚小小的邮票」织进论证，不只结尾升华。
5. **跳脱维度 = 跳出题面预设的二元对立**，重构更高维价值（如「二选一本身就不是赢，真正的赢是同时拥有」）。
6. **论点要「内部分解」**：论点 → 多方向 → 机理分层（表达端/接收端；心态上/过程上），完整细致有层次。

## 2. 维度体系（13 维，四组 + 否决项）

### A 组 · 立意与论点（打什么、怎么立意）

| key | 维度 | 定义 |
|---|---|---|
| `conciseness` | 论点精简·金句化 | 一句话判断句可辩驳，带小金句标签，一语中的 |
| `differentiation` | 论点分工 | 两论不同维度、不重复凑数 |
| `freshness` | 维度跳脱 | 跳出常规轴、重构更高维价值 |
| `decomposition` | 论点内部分解 | 论点拆多方向、机理再分层，完整细致有层次 |

### B 组 · 论证结构（怎么推）

| key | 维度 | 定义 |
|---|---|---|
| `progression` | 逐层递进 | 分小点递进非并列；并列是基线、递进是高分 |
| `case_usage` | 案例运用·比较铺设 | 用生活情景案例铺设框架 + 做比较，生动可感 |
| `mechanism` | 机理支撑 | 专有名词 + 定义，解释「为什么」，不堆名词 |

### C 组 · 语言与价值（有没有高度）

| key | 维度 | 定义 |
|---|---|---|
| `literary_usage` | 文学/生活语句 | 文学语句与生活案例贯穿全文（不只结尾） |
| `value_elevation` | 价值升华 | 落点深、金句收尾、有对抗感 |

### D 组 · 实战可用（能不能用）

| key | 维度 | 定义 |
|---|---|---|
| `field_readiness` | 陈词就绪 | 拿起就念，论点句/过渡句可直接读 |
| `short_attack` | 短打素材 | 自由辩短案例、一句话反制、质询预案 |
| `attack_case_density` | 攻防案例密度 | 攻防里放生活情景案例，不只有逻辑 |

### 否决项（一票否决，另计严重错误率）

| key | 维度 | 定义 |
|---|---|---|
| `fact_caution` | 事实谨慎 | 数据/案例有出处，不编造 |

## 3. 评分体系

### 3.1 两层评分粒度

- **标注粒度**：13 维，每维 1/3/5 分 + 原文定位 + 理由。
- **盲评总分**：聚合为 MVP §4 的 6 维加权（契约要求）。

### 3.2 6 维加权（对齐 MVP §4）

| 维度 | 权重 |
|---|---|
| 题解与判准 | 20% |
| 论点分工 | 20% |
| 机理连贯与深度 | 20% |
| 事实谨慎 / 证据需求 | 15% |
| 攻防与比较 | 15% |
| 实战可用性 | 10% |

### 3.3 1/3/5 行为锚点

- **1** = 缺失或严重错误
- **3** = 基本可用但须明显修改
- **5** = 准确充分、可直接用于备赛

（关键维度锚点示例，见 §2 维度定义；如 `freshness`：1=照搬常规轴、3=换包装但轴不变、5=跳出二元对立且有案例坐实。）

### 3.4 机器 / 人工分离

- **机器自动查**：结构（分层/案例/金句/短打/`ref`/出处/一句话论点句）。
- **人工打分**：质量（精简/生动/价值深度/跳脱成立性），每个分附原文定位 + 一句话理由。

### 3.5 严重错误率（一票否决）

真实来源伪造、关键事实编造 → 另计**严重错误率**，不被文笔/价值分抵消。

## 4. 标注 Schema（JSON 骨架）

```json
{
  "sample_id": "S-001",
  "motion": "...",
  "side": "...",
  "annotator": "B",
  "review_status": "DRAFT",
  "dimensions": [
    {
      "key": "freshness",
      "score": 5,
      "source_of_truth": "human",
      "conventional_axis": "果断弃子=减负高效 vs 舍不得=保留潜力",
      "fresh_axis": "舍不得弃子=同时拥有幸福生活和工作；真正的赢不是二选一",
      "evidence": ["<原文定位>"],
      "rationale": "跳出二元对立、重构更高维价值，且有案例坐实"
    }
  ]
}
```

**每维四要素**：`score`（1/3/5 或 bool）+ `evidence`（原文定位）+ `rationale`（理由）+ `source_of_truth`（`machine` / `ai_infer` / `human`，区分原稿事实 / AI 推断 / 人工确认）。
