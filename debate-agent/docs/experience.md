## 1. 核心设计原则

### 1.1 两层拆解（结构层 vs 质量层）

一篇好框架稿的质量 = **结构层（机器可自动检查）+ 质量层（必须人工判断）**。

- **结构层（机器查与候选标注）**：论点、机理、材料、诠释、攻防的定位与关系；机器可确定检查引用与字段，语义角色仍需人工复核。
- **质量层（人工判）**：论点精不精简、案例生不生动、价值深不深、跳脱维度成不成立、够不够「耳目一新」。

### 1.2 六条关键判断（从具体稿件提炼）

1. **递进 > 并列**：并列不是不好，但逐层递进更有条理、更能说服人。
2. **论点句要「金句化」**：不只一句话可辩驳，还要有能当标签的小金句（如「反目的、反效率」）。
3. **案例要「比较型 + 铺设框架」**：案例用来铺论点框架、做对照（P图 vs 素颜、包装 vs 真实），不是点缀。
4. **文学语句要「贯穿全文」**：「所爱隔山海」「乡愁是一枚小小的邮票」织进论证，不只结尾升华。
5. **跳脱维度 = 跳出题面预设的二元对立**，重构更高维价值（如「二选一本身就不是赢，真正的赢是同时拥有」）。
6. **论点要「内部分解」**：论点 → 多方向 → 机理分层（表达端/接收端；心态上/过程上），完整细致有层次。

### 1.3 学习的是结构关系

背景描述辩题处境和问题；定义/范围确定讨论对象；判准决定比较尺度；主旨由分工不同的论点支持。论点通过机理说明为什么成立，案例/数据/类比服务具体机理环节，诠释把材料与环节、主张、判准连接起来。攻防检查对方异议及我方边界，比较说明为什么我方路径更能满足判准。

关系可写成：`背景 → 问题/判准 → 主旨 → 分工论点 → 机理（条件/过程/后果）`；`案例/数据 → 支持机理 → 诠释回扣`。这是结构图，不要求所有段落按相同顺序或固定层数写。假想场景标 HYPOTHETICAL，类比标 ANALOGY，统计标 DATA，不能混成实证。

文学语句、金句、专有名词和层次节奏属于**独立审美依据**，不作为论证成立的证据，不抵消事实错误；实质价值比较仍属于论证。术语有解释作用时，评价的是解释是否成立，而非是否用了术语。

## 2. 维度体系（细分项供标注，评分以 rubric 0.2.0 为准）

### A 组 · 立意与论点（打什么、怎么立意）

| key | 维度 | 定义 |
|---|---|---|
| `conciseness` | 论点精简·金句化 | 一句话判断句可辩驳，带小金句标签，一语中的 |
| `differentiation` | 论点分工 | 两论不同维度、不重复凑数 |
| `freshness` | 维度跳脱 | 跳出常规轴、重构更高维价值 |
| `decomposition` | 论点内部分解 | 论点拆多方向、机理再分层，完整细致有层次 |

### B 组 · 论证结构（怎么推）

| key | 维度 | 定义 |
|---|---|---|
| `progression` | 逐层递进 | 分小点递进非并列；并列是基线、递进是高分 |
| `case_usage` | 案例运用·比较铺设 | 用生活情景案例铺设框架 + 做比较，生动可感 |
| `mechanism` | 机理支撑 | 专有名词 + 定义，解释「为什么」，不堆名词 |

### C 组 · 语言与价值（有没有高度）

| key | 维度 | 定义 |
|---|---|---|
| `literary_usage` | 文学/生活语句 | 文学语句与生活案例贯穿全文（不只结尾） |
| `value_elevation` | 价值升华 | 落点深、金句收尾、有对抗感 |

### D 组 · 实战可用（能不能用）

| key | 维度 | 定义 |
|---|---|---|
| `field_readiness` | 陈词就绪 | 拿起就念，论点句/过渡句可直接读 |
| `short_attack` | 短打素材 | 自由辩短案例、一句话反制、质询预案 |
| `attack_case_density` | 攻防案例密度 | 攻防里放生活情景案例，不只有逻辑 |

### 否决项（一票否决，另计严重错误率）

| key | 维度 | 定义 |
|---|---|---|
| `fact_caution` | 事实谨慎 | 数据/案例有出处，不编造 |

## 3. 评分体系

### 3.1 两层评分粒度

- **标注粒度**：结构单元及关系先标注，质量分未经人工判断保留 null；不把自动结构标签当专家评分。
- **盲评总分**：六维论证质量加权；文学表达等审美单列，不合入论证总分。详细锚点、2/4、缺项和并列规则见 rubric.md / rubric.json 0.2.0，待用户确认。

### 3.2 6 维加权（对齐 MVP §4）

| 维度 | 权重 |
|---|---|
| 题解与判准 | 20% |
| 论点分工 | 20% |
| 机理连贯与深度 | 20% |
| 事实谨慎 / 证据需求 | 15% |
| 攻防与比较 | 15% |
| 实战可用性 | 10% |

### 3.3 1/3/5 行为锚点

- **1** = 缺失或严重错误
- **3** = 基本可用但须明显修改
- **5** = 准确充分、可直接用于备赛

（关键维度锚点示例，见 §2 维度定义；如 `freshness`：1=照搬常规轴、3=换包装但轴不变、5=跳出二元对立且有案例坐实。）

### 3.4 机器 / 人工分离

- **机器自动查**：结构（分层/案例/金句/短打/`ref`/出处/一句话论点句）。
- **人工打分**：质量（精简/生动/价值深度/跳脱成立性），每个分附原文定位 + 一句话理由。

### 3.5 严重错误率（一票否决）

真实来源伪造、关键事实编造 → 另计**严重错误率**，不被文笔/价值分抵消。

## 4. 标注 Schema（JSON 骨架）

```json
{
  "sample_id": "S-001",
  "motion": "...",
  "side": "...",
  "annotator": "B",
  "review_status": "DRAFT",
  "dimensions": [
    {
      "key": "freshness",
      "score": 5,
      "source_of_truth": "human",
      "conventional_axis": "果断弃子=减负高效 vs 舍不得=保留潜力",
      "fresh_axis": "舍不得弃子=同时拥有幸福生活和工作；真正的赢不是二选一",
      "evidence": ["<原文定位>"],
      "rationale": "跳出二元对立、重构更高维价值，且有案例坐实"
    }
  ]
}
```

**每维四要素**：`score`（1/3/5 或 bool）+ `evidence`（原文定位）+ `rationale`（理由）+ `source_of_truth`（`machine` / `ai_infer` / `human`，区分原稿事实 / AI 推断 / 人工确认）。

## 5. 从具体例子学到的（grounding）

- **「AI 情书」正方** → `decomposition`（论一表达端/接收端、机理心态/过程）、`conciseness` 金句化（反目的、反效率）、`attack_case_density`（女主播运营代聊、别人 10 分钟 vs 我 2 小时、小红书小袁）、`literary_usage` 贯穿（所爱隔山海、乡愁邮票）、`case_usage` 比较（P图 vs 素颜、猜疑 vs 安全感）。
- **「人生如棋」跳脱打法** → `freshness`（舍不得弃子 = 同时拥有幸福生活和工作；底层被压迫者无论选哪个都不是真赢）。
