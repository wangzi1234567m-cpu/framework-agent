# 开发阶段与双人协作

**计划性质：** 里程碑和退出条件，不是已经完成的进度报告。产品方向见 [产品需求](PRODUCT_REQUIREMENTS.md)；具体模块边界与写作方法交付格式见 [架构设计](ARCHITECTURE.md)；首版验收见 [MVP](MVP.md)。

## 1. 双人职责

| 负责人 | 本阶段交付 | 不跨越的边界 |
| --- | --- | --- |
| 系统负责人（你） | Schema、API/身份、数据库与迁移、Application Services、Runner、LLM 适配、Agent 代码与 Skill 加载、前端或最小交互、自动化测试及实验运行 | 不把未经审核的方法当生产 Skill；不能让模型直接改正式业务状态。 |
| 写作方法负责人（她） | 获授权稿件的可追溯标注、写作规则与反例、题解/框架 Skill 和分步 Prompt 草案、质量量表及缺陷案例；参与盲评 | 不必写 Agent Python 代码或直接改公共 Schema、数据库和发布状态；不把原稿事实复制成新题的已核验证据。 |
| 共同 | 确认两种真实稿能容纳于契约；审查规则、Skill、独立测试题与评分量表；复盘失败案例 | 任何字段/方法发布变动要有版本及评审记录。 |

GitHub PR 是推荐的版本审阅方式，但她也可按 [交付契约](ARCHITECTURE.md#6-写作方法负责人交付契约可直接转交) 提交版本化文件，由你审查并入库。仓库是 public：未经授权的稿件或私有用户资料留在仓库外，仓库历史已有材料的授权还须单独核查。当前根目录是 `框架稿/`，应用位于 `debate-agent/`。

## 2. 阶段与退出条件

| 阶段 | 系统负责人 | 写作方法负责人 | 共同退出条件 |
| --- | --- | --- | --- |
| **D0 契约审查** | 冻结两个 Agent 的 DTO、Skill 格式、任务/审批状态边界及首批 API；处理新设计与旧 Schema 的差距 | 用两份已获授权、风格不同的真实稿件校验字段可表达性，提出缺口与歧义 | 两份稿件的题解、论点、嵌套机理、攻防与证据需求可映射；变更有记录，不将旧草案视为正式。 |
| **D1 离线写作验证** | 做模型适配、Skill 加载及两个 Agent 的分析/起草/自审/修订流程，提供合成 fixture 和离线运行脚本 | 两个 Skill/Prompt 草案、来源可追溯规则、正反例与评分量表草案 | 同一批独立题可稳定生成合法 DTO；机器校验和人工发现的错误可回溯到方法版本。 |
| **D2 MVP 业务闭环** | 可信身份/权限、Repository/Service、PG 任务 worker、题解审批、工作区编辑与 Revision、基础 UI/导出及集成测试 | 审核规则、改进自审清单、参与真实题人工使用测试 | 按 [MVP 验收清单](MVP.md#5-端到端验收清单) 完整跑通；迟到任务、重试、错误审批均不能污染用户成果。 |
| **D3 对照实验** | 封存题集，跑 A/B/C 实验，记录成本、时间、结构错误与匿名结果 | 与辩手共同盲评，分析好/坏样本并提出下一版方法 | 预先固定量表和通过门槛后报告整体、分项、严重错误率和失败题；不足时不宣称胜出。 |
| **D4 后续扩展候选** | 按测量结果评估证据溯源、立论稿、局部修改、检索、并发优化 | 探索 RSI 经验沉淀与反馈整理（具体定义待确认） | 逐项形成新的需求和契约再排期，不把愿景直接写入 MVP。 |

阶段允许 D1 与 D2 的独立工作并行，但**D0 契约变化需双方知晓**；D3 可先用离线流程试跑，正式产品结论须说明是否包含人工题解确认、额外模型调用和编辑时间。

- **本轮可独立推进项已实现**：Next.js 本机 Mock 工作台，复用 Service/Runner 的隔离模拟 API；可执行生成、编辑、人工确认与导出。`app.experiments` 可用同一模型、同一请求及相同五段调用预算对比有/无方法包，导出阶段轨迹和匿名评审材料。运行方式见 [README](../README.md)。合成烟测只验证程序。
- **2026-11-19 接入进展**：已快进同步 PR #1（`83180b0`），保留本地未提交系统代码；两套 DRAFT 方法包及评分草案已入库。DeepSeek 真实烟测首轮题解 1/2、框架 2/2 成功；题解 Skill 最终自审阻断定义冲突，失败未丢弃。已修正背景/人群字段的过时方法说明，并将输出 Schema 约束统一到共享运行器；复测与原始交付分别记录。使用包内示例题，未进行独立题盲评，不代表 Skill 效果验收。
- **本机真实工作台**：指定生态文化题的真实题解和框架候选已成功，题解确认显式标记为自动流程测试，不代表用户审核；框架未确认正式版本。长预算、持久本机库、刷新恢复及待审核下载已接通。9份 Markdown 结构候选和三份重点解释、8条来源规则已校验，两套 manifest 已补映射。评分0.2.0草案补独立题解锚点、子项聚合、缺项/并列规则及独立审美，仍待用户确认。
- **未做完**：可信身份接入、真实 PostgreSQL 并发/故障集成验证、经人工批准的 Skill 包、真实生成质量、正式前端身份与持久化接入，以及评分导入、统计和正式 A/B/C 报告。生产 API 默认保持 503，未能供真实用户使用。
- **建议按依赖推进**：用户先审核本次题解和框架；方法负责人复核重点标注、规则/反例与评分草案，共同冻结独立题集与量表。系统负责人继续做身份/PG 验证。草案可在隔离本机或离线实验显式测试，不需要为了测试伪造发布登记；评审通过后才接生产发布。

每次合并检查：契约兼容、来源授权、真实/合成样本标识、版本记录、负例测试、数据权限与用户可见行为。`main` 上的正式方法只能从已审核草案发布；人工确认和版本冲突不得被 Prompt 代替。
